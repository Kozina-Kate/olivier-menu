# Контракт MVP 2: подбор рецептов по продуктам дома

Этот документ фиксирует правила для задач #5, #6 и #13–#18. Изменение
контракта требует обновить backend- и frontend-тесты в том же pull request.

## Модель данных

- `Ingredient` получает стабильный уникальный `slug`, не зависящий от регистра
  и отображаемого русского названия.
- `RecipeIngredient` получает `is_required` с безопасным значением по умолчанию
  `true`. Необязательные специи и добавки не мешают приготовить рецепт.
- Опубликованный рецепт должен содержать хотя бы один обязательный ингредиент.
- Публичный каталог ингредиентов содержит только продукты, используемые хотя бы
  одним опубликованным рецептом.
- Секции имеют фиксированный порядок, не зависящий от сортировки SQLite или
  PostgreSQL. Внутри секции продукты сортируются по отображаемому имени.

## Каталог ингредиентов

`GET /api/v1/ingredients/` возвращает непагинированный список:

```json
[
  {
    "id": 1,
    "slug": "potato",
    "name": "Картофель",
    "section": "vegetables_fruit",
    "section_label": "Овощи и фрукты"
  }
]
```

Черновики не могут сделать ингредиент публичным. Один продукт встречается в
ответе не более одного раза.

## Подбор рецептов

Запрос:

`GET /api/v1/recipes/matches/?ingredients=1,2,3`

Правила входа:

- параметр `ingredients` обязателен;
- ID — положительные целые числа через запятую;
- повторные ID игнорируются;
- пустой параметр, неверный формат и неизвестные или непубличные ID дают `400`;
- ошибка содержит стабильный `code` и списки `invalid_values` или `unknown_ids`.

Ответ:

```json
{
  "count": 1,
  "results": [
    {
      "recipe": {},
      "can_cook": false,
      "match_percent": 75,
      "matched_ingredients": [],
      "missing_ingredients": []
    }
  ]
}
```

`recipe` использует существующий детальный сериализатор рецепта. Элементы в
`matched_ingredients` и `missing_ingredients` содержат `id`, `slug`, `name` и
`is_required`; отдельная модель рецепта на фронтенде не создаётся.

## Формула и сортировка

- `match_percent = round(100 × выбранные обязательные / все обязательные)`;
- `can_cook = true`, если отсутствующих обязательных ингредиентов нет;
- необязательные ингредиенты не входят в знаменатель и не появляются в
  `missing_ingredients`, но выбранные необязательные продукты можно показать в
  `matched_ingredients`;
- рецепты без совпавших обязательных ингредиентов не возвращаются;
- черновики никогда не участвуют в подборе;
- порядок: `can_cook` по убыванию, затем `match_percent` по убыванию, затем
  количество недостающих по возрастанию, затем название рецепта.

Если ни один опубликованный рецепт не имеет совпавшего обязательного продукта,
API возвращает `200` с `count: 0` и пустым `results`.

## Состояние интерфейса

- выбранные продукты сохраняются при поиске, переходе в рецепт и возврате;
- в рамках вкладки выбор хранится в `sessionStorage`;
- `/pantry` показывает отдельные loading, error с повтором и empty states;
- техническая ошибка API не подменяется встроенным рецептом;
- `/menu` продолжает работать при временной недоступности API только через явно
  обозначенный fallback, а не молча.

## Обязательные проверки

- полный, частичный и нулевой результат;
- необязательные ингредиенты;
- дубликаты, неверные и неизвестные ID;
- ингредиенты и рецепты только в черновиках;
- стабильная сортировка и отсутствие N+1-запросов;
- регрессия расчёта меню и списка покупок.
